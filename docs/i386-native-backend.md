# Shared function lowering in the native compiler

`Compiler/I386/BackendCore.HC` contains the production i386 function-lowering loop
and its scalar, floating-point-call, branch and argument helpers. It is included
by both the x64 compiler wrapper and the retained native compiler module. This
removes host allocation and global compiler state from the lowering implementation;
it does not introduce a second restricted instruction generator.

`CI386Backend` supplies the compiler control, output buffer, internal types,
zeroed allocation/release, folding, assembly relocation and diagnostics. The x64
wrapper retains host-only constant/assembler-expression execution and its public
`I386COCCompile`/`CmpI386Buf` entries. Shared `AsmCore.HC` performs inline-assembly
relocation; host assembly-object cleanup remains in `Asm.HC`. Label lookup,
numeric limits and patch-record constants now have shared headers/source.

## Native entry and ownership

CompilerRuntime's `backend(heap, cc, types, out, status)` service runs this shared lowering
loop. It requires a current control owner, a fresh owned output buffer, valid
function IR, private borrowed AOT/function/symbol context, and complete internal
types. Invalid setup returns false. Compilation/allocation failures throw; the
caller must unwind the failed compilation. Arbitrary or malformed graphs are not
validated by this internal entry. The optional status pointer may be zero; otherwise
it receives the current borrowed IR node, stack depth, pass (-2 initialization,
-1 folding, 0/1 lowering, 2 cleanup), and a diagnostic reason when the shared
reporter runs. Bare compiler exceptions may leave reason zero. Inspect node fields
before control cleanup invalidates the graph.

The native adapter sets `CCF_TARGET_I386` and uses the shared native OptPass012
service to fold and refresh operand links. It does not parse source, publish code,
resolve imports or transfer output ownership. The existing AOT backend restrictions
remain, including rejection of host-constant and `#exe` execution through this entry.

Backend allocations have control ownership records (kind 6). Temporary call,
short-circuit and chained-comparison records are explicitly released after success.
Allocation records attached to AOT and symbol structures remain alive until control
cleanup, allowing the enclosing compiler to serialize or resolve them first. Full
unwind reclaims these records independently of graph views, including partial
failure state. They are not ordinary caller-owned heap allocations: do not free
them through symbol destruction or retain their links after control cleanup.
Private borrowed AOT/symbol structures must be discarded or have those links cleared
before reuse. Persistent module/code publication still needs its final owner model.

Output uses the existing owned native builder. On success the IR remains owned by
the control, along with owned literal payloads; the caller can inspect, serialize
or discard it. Generated bytes and relocation metadata remain borrowed until copied
or published under a separate lifetime. Assembly objects supplied through IR remain
the caller's responsibility; this entry does not silently assume ownership of a
borrowed AOT object.

The division template retains 32-bit assembler mode when included in the native
module. Its original x64-host inclusion still restores 64-bit mode. The template's
emitted division instructions and calling convention are shared unchanged. Function
markers delimit the 185-byte inline template; it is code, not a data export or a
callable RET-terminated function. The instruction audit checks its exact frame
setup/teardown, full instruction coverage and internal branch destinations, rejects
calls and returns, and applies the normal 386 opcode checks.

## Interface and validation scope

CompilerRuntime ABI 29 is 168 bytes and includes `backend`, introduced in ABI 22.
Companion services cover [expressions](i386-native-expression.md),
[types](i386-native-type.md), [parser allocations](i386-parser-memory.md) and
[owned token reading](i386-parser-token.md).
FileRuntime ABI 13 validates the new dependency and keeps its 32-byte record.
Compiler/probe imports remain 21/17; the probe remains ABI 5, 56 bytes.

The standalone probe constructs function IR with argument loads, runs both lowering
passes natively, and executes the generated functions. Cases exercise signed and
unsigned arithmetic, division/remainder, shifts across word boundaries, comparisons,
short-circuit branches and a position-independent literal pool. Literal-pool metadata
is checked before ownership cleanup. An exhausted heap forces output allocation
failure inside the actual lowering loop, followed by compiler-control unwind and
exact heap/reference/IF checks.

These native execution cases cover a subset of the shared loop. Cross-host function,
floating-point and inline-assembly suites exercise its broader existing behavior;
passing them does not establish complete native coverage. Native source parsing,
full AOT/JIT linking and publication, top-level execution, `#exe`, public task and
allocation interfaces, DolDoc, self-hosting and strict 386SX/DX acceptance remain
required by `PLAN.md`.

## Normal public COCCompile

Console 257 appends `_COC_COMPILE` and `_COMPILER_BREAK_POLL` after the existing
678 exports. `PublicCompiler.HH` declares the ordinary four-argument COCCompile
interface. First use loads the normal optimizer and then PublicBackendSupport.HC
in Adam, using the guarded shared PublicCompilerContext.HH cache. The guard keeps
mixed optimizer/backend/JIT source loads from redeclaring the context data alias
and triggering the parser's unused-alias warning. Warning checks remain enabled.

CompilerRuntime 96 publishes `_I386_BACKEND_CORE`, a descriptor-based entry to the
same resident production emitter. It validates descriptor size, canonical scalar
types, callbacks and the initial output/AOT context. Public controls are never
cast to private arena controls. ValueClassCore.HC extracts the existing value/type
helpers for both wrappers; CompileFrame.HC supplies temporary expression frames.

PublicBackendCore.HC owns allocations through a per-call tracked workspace.
Function/global proxies isolate generated relocation lists from borrowed symbols.
JIT resolves relative calls and addresses before returning executable heap code;
late external calls retain the original function's mutable executable slot.
AOT stages import/data/poll records and external usages, validates their ownership,
and transfers records into the caller's packet/symbol lists without allocations
in the publication phase. Transferred allocations use standard Free ownership.
Backedge polls use the normal compiler break service; AOT poll records name its
public binding. Debug maps retain line bounds, zero holes and the end sentinel,
using executable addresses for JIT and segment-relative addresses for AOT.

The wrapper restores borrowed context, consumes IR, releases temporary workspace
and returns code independent of the compiler control. It preserves the first
compilation/cleanup exception and frees unpublished code/debug data. Trace requests
call Un rather than silently omitting disassembly; normal disassembler delivery
remains an open dependency. Allocation faults, cancellation, concurrency, complete
assembly/diagnostic behavior and complete public parser delivery remain unqualified.

Compiler ABI 98 adds logical output-window addressing after the existing
CI386Out fields. Host output and the public out_new service keep their contiguous
byte view with a zero window origin and no address callback. Only the retained
frontend selects segmented scratch: sequential emission writes directly into the
current window; relocation patches and the final executable copy use logical
addresses. Each window holds at most 512 data bytes and can shrink to fit a
validated free block. The allocator validates again before committing it. Complete
measured/emitted byte counts, literal bytes, relocation arithmetic and debug maps
remain part of the backend contract.

One registered output header owns the raw window list. Successful deletion and
control unwind both release every window before retiring that header, including
partially completed growth. Its lifetime tag is 8; tag 7 remains the existing
parser pass-stack role. The first compact-ownership candidate reused tag 7 and
failed the unchanged deep-unary diagnostic teardown; that failure is retained in
`build/i386-segmented-diagnostic16-v4`. No diagnostic assertion was removed.

emission pass, before window allocation fragments the remaining space. It attaches
